# 全仓库方案

Python 3.11+ 原生实现，共用 core.py 的运行循环和 SQLite 存储。无运行时第三方依赖。
模型每轮接收请求、可用工具及真实工具历史，只返回一个动作；程序执行工具，再将结果交给模型选择下一步。
Codex CLI、OpenAI 兼容 JSON API、离线 Mock 使用同一接口；CLI 已实测，兼容 API 入口未做真实服务联调。
所有业务成功状态由工具状态构造；模型不能直接指定任务成功。工具校验前置状态与硬性业务约束。
默认最多 16 次模型决策轮次，配置范围 1–64。达到上限或模型异常时明确返回 incomplete，并保存实际已完成结果。
Trace 记录步骤、参数、返回结果和简要动作依据，不记录模型内部思维链。
SQLite 最终交付物主键幂等；检查点是独立的可更新状态。并发同一请求通过原子插入避免重复。

具体调用流程与取舍见 [排期](task1/02-solution.md)、[规划](task2/02-solution.md)、[问答](task3/02-solution.md)、[脚本](task4/02-solution.md)。
